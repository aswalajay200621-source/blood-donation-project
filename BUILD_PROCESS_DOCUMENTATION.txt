1. PROJECT OVERVIEW
================================================================================

Platform Name : Apex Hospital Blood Donation Management & Automated Reminder System
Type          : Full-Stack Medical Web Application (Hospital Staff Portal)
Purpose       : Manage donor registries, enforce mandatory 90-day safety gaps
                between whole blood donations, and automate 3-month recall
                reminder communications across Email (EmailJS) and WhatsApp.

Key Features:
  - Role-based staff authentication (Admin / Staff) with mandatory 2FA
  - Live 6-digit OTP delivered to email inbox via EmailJS on every login
  - Donor Registry: Add, search, filter, view complete donation histories
  - Excel / CSV bulk import with validation, error reporting & dry-run mode
  - Live Camp Entry: Register new donations in real time at blood camp
  - 90-Day Eligibility Engine: Auto-computes next eligible dates per donor
  - Bulk 3-Month Recall Reminder Emails via EmailJS to eligible donors
  - Individual donor recall reminder dispatch from donor profile modal
  - WhatsApp reminder dispatch (mock / Meta Cloud API / Twilio / Gupshup)
  - Notification Audit Log: Track every email/WhatsApp sent, failed, skipped
  - Security Audit Log: Track all login attempts, 2FA events, staff actions
  - System Settings Panel: Configure email, WhatsApp, reminder intervals
  - Fully responsive dark/light hospital UI
  - Deployed live on Vercel (serverless)

5. DATABASE ARCHITECTURE & SCHEMA
================================================================================

Database Engine: PostgreSQL 15 (Supabase cloud) / SQLite 3 (local fallback)

Tables:
-------

1. users
   - id UUID PRIMARY KEY
   - email VARCHAR(255) UNIQUE NOT NULL
   - name VARCHAR(255) NOT NULL
   - password_hash VARCHAR(255) NOT NULL        <- bcrypt hash
   - role VARCHAR(50) CHECK ('admin','staff')
   - two_factor_secret VARCHAR(255)             <- TOTP base32 secret
   - two_factor_enabled BOOLEAN DEFAULT FALSE
   - two_factor_temp_secret VARCHAR(255)        <- Pending 2FA enrollment
   - is_active BOOLEAN DEFAULT TRUE
   - created_at, updated_at TIMESTAMP

2. donors
   - id UUID PRIMARY KEY
   - full_name VARCHAR(255) NOT NULL
   - phone VARCHAR(10) UNIQUE NOT NULL
   - email VARCHAR(255) UNIQUE NOT NULL
   - blood_group VARCHAR(5) CHECK ('A+','A-','B+','B-','AB+','AB-','O+','O-')
   - gender, age, address, camp_location
   - last_donation_date DATE NOT NULL
   - next_eligible_date DATE NOT NULL           <- last_donation_date + 90 days
   - source_of_entry ('Excel Import','Manual Entry')
   - entered_by_staff_id UUID -> users(id)
   - total_donations_count INTEGER DEFAULT 1
   - last_reminder_sent_at TIMESTAMP
   - created_at, updated_at TIMESTAMP

3. donation_history
   - id UUID PRIMARY KEY
   - donor_id UUID -> donors(id) ON DELETE CASCADE
   - donation_date DATE NOT NULL
   - camp_location, units_donated, source
   - entered_by_staff_id UUID -> users(id)
   - notes TEXT
   - created_at TIMESTAMP

4. notification_logs
   - id UUID PRIMARY KEY
   - donor_id UUID -> donors(id)
   - donor_name, channel ('whatsapp','email'), recipient
   - template_type, status ('queued','sent','failed','standby_skipped')
   - provider, response_payload, error_message
   - sent_at, created_at TIMESTAMP

5. audit_logs
   - id UUID PRIMARY KEY
   - user_id UUID -> users(id)
   - user_email, action, resource_type, resource_id
   - ip_address, user_agent
   - details JSONB
   - created_at TIMESTAMP

6. system_settings
   - key VARCHAR(100) PRIMARY KEY
   - value TEXT NOT NULL
   - description TEXT
   - updated_at TIMESTAMP

Indexes:
  - donors(phone), donors(email), donors(next_eligible_date),
    donors(blood_group), donation_history(donor_id),
    audit_logs(action), audit_logs(created_at)

6. BACKEND ARCHITECTURE
================================================================================

Pattern: MVC (Model-View-Controller) with Service Layer

Request Flow:
  HTTP Request
    → vercel.json (rewrite all to /api/index.js)
    → api/index.js (serverless entrypoint, lazy-loads app)
    → app.js (Express middleware chain)
    → authMiddleware.js (JWT token verification)
    → Route handler (e.g., donorRoutes.js)
    → Controller (e.g., donorController.js)
    → Service Layer (e.g., donorService.js)
    → DB Layer (db.js → pg.Pool → Supabase PostgreSQL)
    → Response JSON

Key API Endpoints:
  POST   /api/auth/login              <- Step 1: email + password
  GET    /api/auth/2fa-setup          <- Generate TOTP QR code
  POST   /api/auth/verify-2fa-setup   <- First-time 2FA enrollment
  POST   /api/auth/verify-2fa-login   <- Step 2: TOTP/OTP verification
  POST   /api/auth/refresh            <- JWT access token refresh
  GET    /api/auth/me                 <- Get current user profile

  GET    /api/donors                  <- List donors (filter, paginate, search)
  POST   /api/donors                  <- Register new donor
  GET    /api/donors/:id              <- Get single donor + history
  PUT    /api/donors/:id              <- Update donor record
  DELETE /api/donors/:id              <- Delete donor (admin only)
  POST   /api/donors/:id/send-reminder <- Send recall reminder
  GET    /api/donors/stats            <- Dashboard statistics

  POST   /api/donations               <- Record new donation event

  POST   /api/excel/upload            <- Upload Excel/CSV file
  POST   /api/excel/import            <- Commit validated import

  GET    /api/notifications/logs      <- Notification audit history
  POST   /api/notifications/bulk-whatsapp <- Bulk WhatsApp reminders
  POST   /api/notifications/bulk-email    <- Bulk email reminders
  POST   /api/notifications/test-email    <- Test SMTP connectivity
  POST   /api/notifications/test-whatsapp <- Test WhatsApp connectivity

  GET    /api/settings                <- Fetch all system settings
  PUT    /api/settings/:key           <- Update a system setting
  POST   /api/settings/trigger-cron   <- Manually trigger daily cron job

  GET    /api/audit                   <- Security audit log viewer

  GET    /health                      <- Health check endpoint

Cron Job (Daily Eligibility Scan):
  - Runs at 08:00 AM UTC daily via Vercel Cron
  - Scans all donors where next_eligible_date <= today
  - Dispatches 3-month eligibility reminder via WhatsApp/Email
  - Updates last_reminder_sent_at on donor record
  - Logs all events to notification_logs table

Security Middleware Stack:
  - helmet() : Sets secure HTTP headers
  - cors()   : Allows frontend domain only (FRONTEND_URL env var)
  - express-rate-limit : 100 req/15min global, 5 login attempts/15min
  - verifyToken() : Validates Bearer JWT on all protected routes
  - requireRole(['admin']) : Admin-only route guard
  - auditMiddleware : Auto-logs sensitive operations

2FA Login Flow (Backend):
  Step 1: POST /api/auth/login
    - Validates email + bcrypt password
    - Generates 6-digit email OTP (Math.random)
    - Signs temp JWT: { userId, purpose: '2FA_VERIFICATION', emailOtp }
    - Returns: temp2FAToken, emailOtp, destinationEmail, require2FA: true
  Step 2: POST /api/auth/verify-2fa-login
    - Verifies temp JWT signature + expiry (5 min)
    - Accepts: emailOtp (from email) OR TOTP (authenticator app) OR demo code
    - On success: issues 15-min access JWT + 7-day refresh JWT
    - Records LOGIN_SUCCESS to audit_logs

8. AUTHENTICATION & SECURITY SYSTEM
================================================================================

Login Flow (Step by Step):
  1. User opens app at blood-donation-project-pi.vercel.app
  2. LoginModal shows (CREDENTIALS step)
  3. User enters email + password (or clicks one-click demo button)
  4. Frontend: POST /api/auth/login
  5. Backend: validates credentials, generates 6-digit emailOtp,
              embeds in temp JWT (5-min expiry)
  6. Backend returns: temp2FAToken + emailOtp + destinationEmail
  7. Frontend: calls sendOtpEmail() via EmailJS → email sent to inbox
  8. LoginModal transitions to 2FA_VERIFY step
  9. UI shows: "✅ 6-digit code sent to [email]. Check your inbox."
  10. User opens email, copies 6-digit code
  11. User enters code in OTP input field
  12. Frontend: POST /api/auth/verify-2fa-login
  13. Backend: decodes temp JWT, compares codes, issues full JWTs
  14. Frontend: stores access + refresh tokens in localStorage
  15. App unlocks: full hospital dashboard accessible

OTP Code Priority (Backend Accepts):
  1. Email OTP (live code from inbox) - PRIMARY
  2. TOTP (Google/Microsoft Authenticator app code) - SECONDARY
  3. Demo codes: 123456 or 000000 - ALWAYS WORKS (for demo purposes)

Token Lifetimes:
  - Access Token  : 15 minutes
  - Refresh Token : 7 days
  - Temp 2FA Token: 5 minutes

Password Hashing: bcrypt with saltRounds=10

Audit Events Logged:
  LOGIN_SUCCESS, LOGIN_FAILED, 2FA_ENABLED, 2FA_VERIFY_FAILED

Default Admin TOTP Secret (pre-seeded): JBSWY3DPEHPK3PXP

9. EMAIL INTEGRATION (EMAILJS)
================================================================================

Why EmailJS instead of Nodemailer/SMTP?
  - Vercel serverless functions cannot maintain persistent SMTP connections
  - EmailJS runs entirely in the browser (client-side SDK)
  - No email server credentials needed on the backend
  - Free tier: 200 emails/month, no credit card required
  - Gmail OAuth: no plain-text password storage

EmailJS Setup:
  - Account   : ASWAL S AJAY (dashboard.emailjs.com)
  - Service   : Gmail (service_eblorag) - Connected as aswalajay200621@gmail.com
  - Templates :
      template_uts7pu3 : 2FA OTP Code
        Subject : "Your Hospital Portal 2FA Code: {{otp_code}}"
        Body    : 6-digit {{otp_code}} display
        To Email: {{to_email}}
      template_pfqixi4 : 3-Month Donor Recall Reminder
        Subject : "🩸 You are eligible to donate blood again, {{donor_name}}!"
        Body    : Personalized reminder with name, blood group, last donation date
        To Email: {{to_email}}

How Reminder Emails Work:
  - Individual: Click "Send Recall Reminder" on a donor profile
      → DonorDetailsModal calls sendDonorReminderEmail(donor)
      → EmailJS sends personalized email to donor.email
  - Bulk: Click "Email All Eligible" in Notifications view
      → Fetches all eligible donors from API
      → Iterates first 5 (monthly limit protection)
      → Sends personalized reminder email to each via EmailJS
      → Shows success/error status banner
